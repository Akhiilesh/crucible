Only proven bugs reach the reviewer.

IBM Bob attacks a pull request from four angles at once. Crucible keeps a finding only if a test proves it, then the bug is fixed and the proof stays as a regression test. The AI raises suspicions; a strict, deterministic verifier decides.

How it works

1
Read intent
Reads the diff, ticket and spec; lists the rules the PR must obey.
IBM Bob
2
Attack ×4, in parallel
Edge, security, state and spec attackers each write tests that should break the PR.
IBM Bob subagents
3
Verify: 4 proof gates
Fails on the PR, caused by the PR, fails 3 of 3 runs, cites a real rule. Else: noise.
Crucible CLI · no AI
4
Fix
Patch until every proof test passes; conflicts are flagged for a human.
Fixer playbook
5
Report
Each proven bug with its rule, proof test, fix and red → green status.

Try it yourself

1Get Crucible and the demo repository

The demo repo is a small FastAPI orders service with three pull requests (bugs planted on purpose) and IBM Bob's attacker output for each one.

2Run the web app on your machine

git clone <this repo> crucible && cd crucible
python3 -m venv .venv && .venv/bin/pip install -e .
.venv/bin/python -m crucible.cli serve        # opens on http://127.0.0.1:8765

Upload the demo .zip, choose base main, a PR branch and its runs/<pr> folder, then click Run proof gates. Each run takes about 10–20 seconds.
